## 1. Verdict

**READY FOR PI DRY RUNS. NOT READY TO ARM.**

The code can go to the Pi for DRY-1 / DRY-2 now. It must not be armed (`mode=live` + ARM) until the Kite behaviours in
§6 are seen on the Pi; three of them decide whether any order is placed at all (circuit-limit field, tick sizes, the
order-book state right after an order) and one decides whether the 16:00 check tells the truth (holdings on the buy
day). The new lock and process-group code has only ever run on Windows: the unit suite must pass on the Pi first.

Before this review the code was **not** safe to arm: one Critical and seven High problems (below). All eight are fixed
and tested. Nothing in the review found a path that places a duplicate order or an order outside the envelope
(LIMIT / CNC / DAY, quantity × cap ≤ earmark): the journal-before-call order and the tag guard held up under every crash
point traced.

## 6. Must be verified on the Pi before arming

0. **Run the unit suite on the Pi** (`.venv/bin/python -m unittest discover -s tests`): the journal append lock
   (`fcntl`) and the vet's process-group kill (`killpg`) are POSIX branches that have never executed (PC = Windows).
   Spec §K wants the tests on the Pi anyway.

Order path (DRY-2 and T6 show most of these with no order):
1. Quote fields on a non-F&O name at ~15:10: `upper_circuit_limit` present and non-zero (else **no buy at all**, F13).
2. Instruments: `tick_size` present for every plan symbol (else OWNER_HOLD, F15 / F21); BE names appear as `SYM-BE`.
3. Margins: which of `equity.net` / `equity.available.live_balance` is cash usable for CNC (N1). The code takes the
   smaller.
4. Order book row of a REJECTED order: `status` = `REJECTED` and the reason in `status_message` (F02 depends on it);
   the texts for no funds, price band, market closed (classifier is by keywords; unknown → OWNER_HOLD).
5. The probe: how long after the order id returns the row shows `OPEN` with its tag (N3), and which transient states
   appear before it. Longer than `probe_reads` × `probe_wait_s` → the probe fails every day. Tag length / characters
   (U1).
6. `trades()` rows carry `order_id`, `trade_id`, `quantity`, `average_price` (U28). If not, fills are booked from the
   order row with an alert (F16).
7. Holdings on the buy day at 16:00 and the next morning: are today's CNC buys in `quantity + t1_quantity` (U6)?
   Either is accepted at 16:00; the next morning they MUST be there or the preflight stops the retries.
8. Three MODIFYs on one order, and a MODIFY of a partly filled order keeps id and filled quantity (U24, N2).
